# 评测数据自检 Checklist

给测试分析工具造"带标准答案的卷子"时，逐项过一遍。每条都是本轮闭环回归
（60 例、含 26 条贴边界/对抗样本）实际踩过或守住的结论，不是泛泛而谈。

## 一、真值可信度（先查这个，不过关后面全白做）

- [ ] **真值不是"注入了什么"**。若真值记录的是生成参数（"我在 5.0 秒注入了
      3 秒急刹"），而工具按同一套口径检测——两边共享假设，检出率 100% 只证明
      代码没写岔，不证明任何事。**真值必须由一份独立实现从数据里算出来。**
- [ ] **参考实现只照抄口径常量，不共用代码**。与工具同源的工具函数不算独立；
      两个实现一致才是"双方对口径理解一致"的证据。
- [ ] **回归时逐条比对两边的事件集**，不是只比总数。总数相等但区间错位
      （比如一边 [4.9,5.9] 一边 [5.0,6.0]）是边界语义分歧，比漏检更危险。
- [ ] **诚实声明数据等级**。生成的是公式合成的运动学级序列（时间-速度），
      就在 source.json 里写明，不冒充道路采集、不冒充闭环仿真。评测结论的
      适用范围随之声明：运动学口径成立，不代表真实噪声结构下成立。

## 二、对抗样本：参数范围按"结论必须成立"反推

造贴边界样本时，**先写死这条样本要证明什么，再反推参数上限**，而不是先随便
选范围再看结果：

- [ ] **"应无事件"的样本**，参数上界乘以最坏取整后仍够不到门槛。
      例：短急减样本要证明"下降间隔不够 4 个"，dip 上限取 0.34 秒——
      因为 0.35 抖出来会被取整圆成 0.4，样本悄悄变成"应有事件"的另一类，
      结论直接泄露。
- [ ] **"应有事件"的样本**，参数下界要留足余量。例：典型组减速度下限
      2.2 m/s²，保证 0.5 秒窗口降幅 ≥ 1.0 m/s 跨过门槛。
- [ ] **联合约束单独验**。单个参数合法不代表组合合法：末端车速至少保留
      3 m/s 余量，否则长时长 + 大减速度会造出"减速到停止"的非法场景。
- [ ] **每个模板配一条形状单测**，直接断言速度曲线在关键时间点的值，
      而不是只断言事件有无。形状错了，事件可能"碰巧"还对，但样本已经变质。
- [ ] **对抗组占足够比例**。混合批次里对抗组低于两成，边界情况基本跑不到；
      本轮配比：典型组六成、对抗组三成、负样本一成。

## 三、双层口径，分开读指标

工具的设计若是"宽筛 + 复核"（筛查门槛比事件口径宽），指标必须分两层，
混在一起读会得出错误结论：

- [ ] **检出率/误报率归宽筛层**。宽筛门槛更松，协议事件理应 100% 被候选
      覆盖——这个 100% 是可证明的，不是业绩。宽筛捞出无事件样本是设计使然，
      量化它（如本轮 15.1%）是为了说明固有成本，**不代表工具在真实数据上
      会误报**。
- [ ] **"口径误判"单独一类，且必须是 0**。定义：候选被工具自判"符合口径"
      （meets_numeric_rule），却没有真值事件支撑。**这才是实现 bug**；
      宽筛噪声（自判 below_numeric_rule）不是。
- [ ] **结构不一致单独一类**。有真值事件但候选簇数 ≠ 事件数 = 合并过头或
      切碎，检出率 100% 也掩盖了它。注意只在有事件的案例上计——
      负样本天然"1 候选 vs 0 事件"，算进去是指标虚高。
- [ ] **误报按候选簇计，不按候选项计**。接力候选（两个候选接力覆盖同一事件）
      各算一次会重复计数，虚高误报率。

## 四、工程细节（每条都实际咬过人）

- [ ] **时间参数对齐采样网格**。制动窗落在半个间隔上，"应有结论"没法手算
      复核，测试期望值全靠猜。
- [ ] **取整会改样本类别**。范围上限先想好取整方向：向下取整更保守，
      向上取整可能把样本推进另一类（见第二条短急减）。
- [ ] **查询条件类参数（如 --profiles 子集）不原地改全局配置**。同进程内
      跑第二批会继承上一批的配比，混进不该出现的模板，且不报错。
- [ ] **旧库打开要幂等补建新表并升版本号**（PRAGMA user_version 比大小，
      不是比是否为零）。加表不加迁移，老用户的库直接缺表。
- [ ] **导出物带 manifest**。下游拿一份清单（suite 元信息 + 逐场景真值 +
      指纹）即可对答案，不必解析每份 truth.json；指纹用于校验传输无损。

## 五、报告可读性

- [ ] **结论必须配"怎么读"**。100% 检出旁边必须写清它是可证明的、以及本轮
      真正守的是什么（如"口径误判 0 + 两边实现逐条一致"）。只报数字不写读法，
      看报告的人（包括三个月后的自己）会过度解读。
- [ ] **已知边界写进 README**，包括"参考实现不是第三方标准"这类诚实声明。
      面试被追问时，这份清单就是答题提纲。
